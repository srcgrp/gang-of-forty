# طراحی فروشگاه در یک صفحه

## ۱. نیازمندی‌ها

کاربر می‌تواند دسته‌بندی‌ها، تخفیف‌ها، بنرها و کالاها را ببیند، در کالاها جستجو و فیلتر کند و کالا را به سبد خرید اضافه کند. سبد و فیلتر بعد از Refresh یا Back/Forward حفظ می‌شوند.

عمداً خارج از این نسخه است: ثبت سفارش واقعی، پرداخت و صفحهٔ کامل سبد خرید.

## ۲. بخش‌های صفحه

نوار اطلاع‌رسانی، هدر چسبان با لوگوی SVG، جستجو و منو، بنر اصلی و بنرهای جانبی، دسته‌بندی‌ها، کاروسل‌های محصول، بنرهای تبلیغاتی، فهرست نتایج جستجو و فوتر. محتوای بنرها و کاروسل‌ها از `home.json` می‌آید.

## ۳. داده‌ها و صاحبشان

| داده | کجا زندگی می‌کند | کامپوننت صاحب / مسئول | چه کسی عوضش می‌کند | کجا ذخیره می‌شود |
|---|---|---|---|---|
| وضعیت دریافت اطلاعات (`LoadState`) | `App.tsx` | `App` | Effect دریافت API | فقط حافظه React |
| دسته‌بندی انتخاب‌شده (`categoryId`) | `App.tsx` | `App` | `CategoryNav` از طریق `onPick` | فقط حافظه React |
| سبد خرید (`cart`) | `App.tsx` | `App` | `ProductGrid` از طریق `onAdd` و `CartPanel` از طریق `onRemove` | `localStorage` با `storage/cart.ts` |
| محصولات، دسته‌بندی‌ها، بنرها و اطلاعات فروشگاه | API و سپس `LoadState` | `App` دریافت می‌کند و به فرزندان می‌دهد | سرور | پاسخ API؛ در این برنامه فقط در حافظه React |

مقادیر محاسبه‌شده مثل `lines`، `total` و تعداد کالاهای سبد، از روی `cart` و محصولات هنگام Render محاسبه می‌شوند؛ بنابراین State جداگانه نیستند. نگهداری هم‌زمان مقدار اصلی و نتیجه محاسبه‌شده می‌تواند باعث ناسازگاری آن‌ها شود.

قیمت هرگز از `localStorage` خوانده نمی‌شود و همیشه از API می‌آید. در `localStorage` فقط شناسه و تعداد هر محصول ذخیره می‌شود.

## ۴. قرارداد API

شش فایل `products`، `categories`، `stock`، `offers`، `home` و `shop` (با پسوند `.json`) هنگام شروع، به‌صورت موازی و با `cache: 'no-store'` دریافت می‌شوند. شکل هر کدام در `src/types.ts` تعریف شده است. `getJSON` خروجی `unknown` می‌دهد و هر فایل قبل از استفاده از Guard مخصوص خودش می‌گذرد (`isProduct`، `isCategory`، `isOffer`، `isStock` و ...).

## ۵. حالت‌ها

هر بخش از `LoadState` استفاده می‌کند: `loading`، `success`، `empty` و `error`.

- **loading:** Skeleton؛ اگر بیش از ۲ ثانیه طول بکشد، پیام هشدار دربارهٔ کندی یا قطعی اتصال هم نشان داده می‌شود.
- **empty:** فروشگاه بدون محصول، یا جستجویی که نتیجه ندارد.
- **error:** پیام قابل‌فهم و دکمهٔ «تلاش دوباره». اگر پاسخ تا ۱۲ ثانیه نرسد درخواست لغو می‌شود.
- رکوردهای نامعتبر حذف می‌شوند و تعدادشان در Console نوشته می‌شود.

نمایش حالت‌ها با `switch` است و `default` آن بررسی `never` دارد.

## ۶. درخت کامپوننت‌ها و پوشه‌ها

درخت کامپوننت‌های صفحه:

```text
App
├─ Header
├─ main
│  ├─ Hero
│  ├─ CategoryNav
│  └─ shop-layout
│     ├─ ProductGrid
│     └─ CartPanel
└─ Footer

ProductGrid
└─ ProductCard × n

CartPanel
└─ ردیف‌های سبد خرید
```

ساختار پوشه‌ها و مسئولیت آن‌ها:

```text
src/
  types.ts              ← نوع‌های مشترک
  api/                  ← دریافت داده و Guardهای API
  data/                 ← اعتبارسنجی مشترک
  storage/              ← خواندن و نوشتن سبد در localStorage و URL
  features/
    cart/               ← توابع خالص قوانین و محاسبات سبد
    products/           ← انتخاب و فیلتر محصولات
  components/           ← کامپوننت‌های قابل استفاده در رابط React
  App.tsx               ← State، Effectها و اتصال کامپوننت‌ها
  main.tsx              ← نقطه ورود React و رندر App در root
```

`App` مالک Stateهای اصلی است و داده‌ها یا callbackها را با `props` به کامپوننت‌های فرزند می‌دهد. کامپوننت‌های فرزند مستقیماً State والد را تغییر نمی‌دهند؛ رویدادها را از طریق callback prop گزارش می‌کنند.

`api/` مسئول دریافت داده از شبکه و `storage/` مسئول دسترسی به `localStorage` است. قوانین سبد و انتخاب محصولات در توابع مستقل `features/` قرار دارند. `main.tsx` فقط برنامه React را به عنصر `root` متصل می‌کند.

## ۷. امنیت

هر چیزی که در مرورگر است قابل دیدن و تغییر است: Bundle، متغیرهای `VITE_`، پاسخ API و `localStorage`؛ پس هیچ رمز یا کلیدی در `.env` نمی‌گذاریم. متن‌ها با `textContent` وارد صفحه می‌شوند تا داده‌های API به‌عنوان HTML تفسیر نشوند، رنگ‌ها فقط Hex معتبر و لینک‌ها فقط Fragment معتبر می‌پذیرند.

جمع نهایی سبد باید در سرور حساب شود، چون کاربر می‌تواند `localStorage` را دستکاری کند یا درخواست را با قیمت و تعداد دلخواه بفرستد. عددی که مرورگر می‌فرستد فقط یک درخواست است، نه مبلغ قطعی.

خروجی `dist` با `base: './'` برای مسیر `/shops/<slug>/` ساخته می‌شود. API در توسعه `/api` و در نسخهٔ تولید `../../api` است.
