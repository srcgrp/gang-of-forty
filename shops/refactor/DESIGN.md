# توضیحات پروژه فروشگاه

## ۱. نیازمندی‌های پروژه

هدف این پروژه پیاده‌سازی فروشگاه بر اساس PDFهای چهار هفته دوره است. بخش‌های اصلی شامل نمایش دسته‌بندی‌ها، تخفیف‌ها، موجودی کالاها، بنرها و اطلاعات تماس از طریق API است. همچنین امکان اضافه کردن کالا به سبد خرید و نمایش تعداد آن‌ها وجود دارد و اطلاعات سبد بعد از رفرش صفحه هم باقی می‌ماند.

دسته‌بندی و جستجو از طریق URL مدیریت می‌شوند تا با رفرش صفحه یا استفاده از دکمه‌های Back و Forward مرورگر، وضعیت قبلی قابل بازیابی باشد.

در این نسخه امکان ثبت سفارش واقعی، پرداخت و نمایش کامل سبد خرید پیاده‌سازی نشده است.

## ۲. بخش‌های مختلف صفحه

صفحه فروشگاه شامل نوار اطلاع‌رسانی، هدر چسبان، لوگوی اصلی SVG، بخش جستجو، منو، بنر اصلی و بنرهای جانبی، دسته‌بندی‌ها، کاروسل محصولات، بنرهای تبلیغاتی و فوتر است.

اطلاعات مربوط به بنرها و کاروسل‌ها از `home.json` دریافت می‌شوند. در حالت عادی فقط کاروسل‌هایی نمایش داده می‌شوند که در همین فایل تعریف شده‌اند. اگر یک دسته‌بندی کاروسل آماده نداشته باشد، بخش مربوط به آن هنگام نیاز ساخته می‌شود.

وقتی کاربر جستجو یا فیلتر دسته‌بندی را انجام می‌دهد، فقط کالاهایی نمایش داده می‌شوند که با نتیجه انتخاب‌شده مطابقت دارند.

## ۳. دریافت داده‌ها و مدیریت وضعیت

اطلاعات محصولات، قیمت‌ها، موجودی، تخفیف‌ها، دسته‌بندی‌ها و محتوای فروشگاه از API دریافت می‌شوند.

مدیریت وضعیت کلی برنامه و هماهنگی بین بخش‌های مختلف در `main.ts` انجام می‌شود. اطلاعات سبد خرید در `localStorage` ذخیره می‌شوند؛ اما فقط شناسه کالا و تعداد آن نگهداری می‌شود. قیمت کالا از اطلاعات ذخیره‌شده در مرورگر گرفته نمی‌شود و از داده‌های API به دست می‌آید.

پارامترهای `cat` و `q` در URL برای نگهداری وضعیت دسته‌بندی و جستجو استفاده می‌شوند.

همچنین مقدار `VITE_API_URL` در زمان Build در دسترس کد سمت کاربر قرار می‌گیرد؛ بنابراین نباید اطلاعات محرمانه در این متغیر قرار داده شود.

## ۴. ساختار داده‌های API

هر فایل API اطلاعات مشخصی را در اختیار برنامه قرار می‌دهد:

- `products.json`: اطلاعات محصولات مثل شناسه، شناسه دسته‌بندی، نام، ایموجی، واحد، قیمت و برچسب‌ها.
- `categories.json`: اطلاعات دسته‌بندی‌ها شامل شناسه، نامک، نام، ایموجی و رنگ.
- `stock.json`: زمان آخرین به‌روزرسانی موجودی و تعداد موجود هر کالا.
- `offers.json`: شناسه محصول، درصد تخفیف و عنوان تخفیف.
- `home.json`: اطلاعات بنر اصلی، بنرهای جانبی، بنرهای تبلیغاتی و کاروسل‌های صفحه اصلی.
- `shop.json`: اطلاعات فروشگاه شامل متن‌ها، شماره تماس، آدرس، هزینه ارسال، مبلغ ارسال رایگان، منو، راهنما، ساعات کاری و اطلاعات کپی‌رایت.

اطلاعات هر فایل متناسب با نیاز بخش‌های مختلف برنامه استفاده می‌شوند و فیلدهایی که کاربردی ندارند وارد منطق برنامه نمی‌شوند.

## ۵. مدیریت وضعیت‌ها و خطاها

برای مشخص کردن وضعیت دریافت و نمایش اطلاعات، از `LoadState` استفاده شده است که چهار حالت `loading`، `success`، `empty` و `error` را پوشش می‌دهد.

برای هر وضعیت، نمایش مناسب در نظر گرفته شده است. هنگام بارگذاری، Skeleton نمایش داده می‌شود و اگر دریافت اطلاعات بیشتر از دو ثانیه طول بکشد، پیام هشدار ظاهر می‌شود. همچنین بعد از ۱۲ ثانیه امکان لغو عملیات وجود دارد و در صورت خطا، کاربر می‌تواند دوباره تلاش کند.

برای مواردی مثل خالی بودن نتیجه جستجو، ناشناخته بودن دسته‌بندی، نامعتبر بودن اطلاعات، تمام شدن موجودی و خطای ذخیره‌سازی نیز پیام مناسب نمایش داده می‌شود.

قبل از استفاده از پاسخ API، اعتبار داده‌ها بررسی می‌شود تا اطلاعات نامعتبر مستقیماً وارد منطق اصلی برنامه نشوند. در بخش‌هایی که از `switch` برای بررسی وضعیت استفاده شده، بررسی `never` نیز برای پوشش حالت‌های تعریف‌شده در TypeScript در نظر گرفته شده است.

## ۶. ساختار فایل‌ها و وابستگی‌ها

ساختار پروژه به چند بخش تقسیم شده تا مسئولیت هر فایل مشخص باشد.

`main.ts` وظیفه هماهنگی بین بخش‌های مختلف را بر عهده دارد. بخش `ui` برای نمایش رابط کاربری استفاده می‌شود و فقط به فایل‌های رابط کاربری و انواع داده وابستگی دارد.

منطق مربوط به آماده‌سازی داده‌ها در `features` قرار گرفته است. بخش‌های `features/catalog` و `features/cart` مستقل از رابط کاربری هستند و فقط مدل‌های موردنیاز را می‌شناسند. انتخاب نتایج جستجو و فیلتر نیز در `main.ts` انجام می‌شود.

فایل `ui/dom.ts` برای ساخت عناصر DOM و فایل `ui/format.ts` برای قالب‌بندی اطلاعاتی مثل قیمت استفاده می‌شوند.

بخش‌های `api`، `storage` و `data` مسئول ارتباط با API، ذخیره‌سازی، اعتبارسنجی و مدیریت URL هستند. فایل `types.ts` نیز مدل‌های داده و انواع callbackها را تعریف می‌کند.

در طراحی این ساختار تلاش شده وابستگی‌ها یک‌طرفه باشند، چرخه بین ماژول‌ها ایجاد نشود و فایل‌ها تا حد امکان کمتر از ۲۰۰ خط باقی بمانند. رعایت این موارد با Checker دوره بررسی می‌شود.

## ۷. اعتبارسنجی، امنیت و انتشار

تابع `getJSON` اطلاعات دریافتی را به شکل `Promise<unknown>` برمی‌گرداند تا قبل از استفاده، نوع و ساختار داده‌ها بررسی شود.

برای محصولات، دسته‌بندی‌ها، تخفیف‌ها، موجودی و ساختار اطلاعات صفحه اصلی و فروشگاه، Guardهای مناسب در نظر گرفته شده‌اند. اگر داده‌ای نامعتبر باشد، بسته به نوع خطا گزارش می‌شود، کنار گذاشته می‌شود یا خطای قابل فهمی به کاربر نمایش داده می‌شود.

برای جلوگیری از تفسیر داده‌های API به‌عنوان HTML، از روش‌هایی مثل `createElement` و `textContent` استفاده می‌شود. همچنین لینک‌ها به Fragmentهای معتبر محدود شده‌اند و رنگ‌ها فقط در قالب Hex معتبر پذیرفته می‌شوند.

اطلاعات سبد خرید نیز از نظر شناسه کالا و تعداد بررسی می‌شوند و تعداد کالاها با موجودی آن‌ها هماهنگ می‌شود. با این حال، در صورت اضافه شدن قابلیت ثبت سفارش واقعی، محاسبه نهایی مبلغ و بررسی قیمت و موجودی باید در سمت سرور انجام شود.

برای اجرای پروژه، مقدار `base` در Vite برابر `./` است. مسیر API در محیط توسعه `/api` و در نسخه تولید `../../api` در نظر گرفته شده است.

در نهایت، خروجی `dist` برای استقرار پروژه در مسیر `/shops/<slug>/` روی میزبانی که API مشترک دارد آماده می‌شود. متغیرهای محیطی با پیشوند `VITE_` نیز عمومی هستند و محل مناسبی برای نگهداری اطلاعات محرمانه نیستند.
