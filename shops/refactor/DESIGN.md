# طراحی فروشگاه در یک صفحه

## ۱. نیازمندی‌ها

کاربر می‌تواند دسته‌بندی‌ها، تخفیف‌ها، بنرها و کالاها را ببیند، در کالاها جستجو و فیلتر کند و کالا را به سبد خرید اضافه کند. سبد و فیلتر بعد از Refresh یا Back/Forward حفظ می‌شوند.


## ۲. بخش‌های صفحه

نوار اطلاع‌رسانی، هدر چسبان با لوگوی SVG، جستجو و منو، بنر اصلی و بنرهای جانبی، دسته‌بندی‌ها، نوار پیشنهاد شگفت‌انگیز با شمارش معکوس، فهرست کالاها، کشوی سبد خرید (چسبیده به لبهٔ چپ صفحه با ردیف «جمع سبد خرید» در پایین) و فوتر. محتوای بنرها از `home.json` می‌آید.

فهرست کالاها در نمای اصلی ۱۲ کالای اول را نشان می‌دهد و دکمهٔ «نمایش بیشتر/کمتر» زیر شبکهٔ کالاها (داخل همان کانتینر صفحه) فهرست را تا کامل باز و دوباره به ۱۲ کالا جمع می‌کند؛ در زمان جستجو یا فیلتر دسته، همهٔ نتایج بدون دکمهٔ بازوبستن نمایش داده می‌شوند. دکمهٔ «نمایش شگفت‌انگیز» بعد از بستن نوار حراج، روبه‌روی عنوان بخش کالاها می‌آید. با افزودن هر کالا به سبد، افکت کتابخانهٔ `canvas-confetti` اجرا می‌شود. لیست کالاهای کشوی سبد خرید اسکرول نازک و هم‌تم دارد.

## ۳. داده‌ها و صاحبشان

| داده | کجا زندگی می‌کند | کامپوننت صاحب / مسئول | چه کسی عوضش می‌کند | کجا ذخیره می‌شود |
|---|---|---|---|---|
| وضعیت دریافت اطلاعات (`LoadState`) | `App.tsx` | `App` | Effect دریافت API | فقط حافظه React |
| دسته‌بندی انتخاب‌شده (`categoryId`) | `App.tsx` | `App` | `CategoryNav` و `MainNav` از طریق `onPick` | فقط حافظه React |
| عبارت جستجو (`query`) | `App.tsx` | `App` | `SearchBox` از طریق `onQuery` | فقط حافظه React |
| سبد خرید (`cart`) | `App.tsx` | `App` | `ProductGrid` از طریق `onAdd` و `CartPanel` از طریق `onRemove` و `onQuantity` | `localStorage` با `storage/cart.ts` |
| باز بودن کشوی سبد و نمایش شمارش معکوس | `App.tsx` | `App` | `Header` و `CartPanel` و دکمهٔ «نمایش شگفت‌انگیز» | فقط حافظه React |
| نمایش کامل فهرست کالاها (`showAll`) | `App.tsx` | `App` | دکمهٔ «نمایش بیشتر/کمتر» از طریق `onToggleAll` | فقط حافظه React |
| محصولات، دسته‌بندی‌ها، بنرها و اطلاعات فروشگاه | API و سپس `LoadState` | `App` دریافت می‌کند و به فرزندان می‌دهد | سرور | پاسخ API؛ در این برنامه فقط در حافظه React |

مقادیر محاسبه‌شده مثل `lines`، `total`، تعداد سبد و نتیجهٔ جستجو، از روی `cart`، دستهٔ انتخاب‌شده و عبارت جستجو هنگام Render محاسبه می‌شوند؛ بنابراین State جداگانه نیستند. نگهداری هم‌زمان مقدار اصلی و نتیجهٔ محاسبه‌شده می‌تواند باعث ناسازگاری آن‌ها شود.

قیمت هرگز از `localStorage` خوانده نمی‌شود و همیشه از API می‌آید. در `localStorage` فقط شناسه و تعداد هر محصول ذخیره می‌شود.

## ۴. قرارداد API

شش فایل `products`، `categories`، `stock`، `offers`، `home` و `shop` (با پسوند `.json`) هنگام شروع، هم‌زمان و موازی با `Promise.all` دریافت می‌شوند. شکل هر کدام در `src/types.ts` تعریف شده است. `getJSON` خروجی `unknown` می‌دهد و هر فایل قبل از استفاده از Guard مخصوص خودش می‌گذرد (`isProduct`، `isCategory`، `isOffer`، `isStock` و ...).



## 5. درخت کامپوننت‌ها و پوشه‌ها

درخت کامپوننت‌های صفحه:

```text
App
├─ Status            (تا وقتی داده نیامده)
└─ ShopPage
   ├─ Header
   │  ├─ Logo
   │  ├─ SearchBox
   │  └─ MainNav
   ├─ Hero
   ├─ CategoryNav
   ├─ SaleCountdown
   ├─ ProductGrid
   │  └─ ProductCard × n
   ├─ Footer
   └─ CartPanel      (کشوی چپ)
```

ساختار پوشه‌ها و مسئولیت آن‌ها:

```text
src/
  types.ts              ← نوع‌های مشترک
  api/                  ← دریافت داده و Guardهای API
  data/                 ← اعتبارسنجی مشترک
  storage/              ← خواندن و نوشتن سبد در localStorage
  features/
    cart/               ← توابع خالص قوانین و محاسبات سبد
    products/           ← انتخاب و فیلتر محصولات
  components/           ← کامپوننت‌های قابل استفاده در رابط React
    shop-page.types.ts   ← نوع Props صفحه فروشگاه
  App.tsx               ← Stateها، Effectهای واکشی و ذخیره‌سازی و توابع رویداد
  main.tsx              ← نقطه ورود React و رندر App در root
```

`App` مالک Stateهای اصلی است و داده‌ها یا callbackها را با `props` به `ShopPage` و کامپوننت‌های فرزند می‌دهد. کامپوننت‌های فرزند مستقیماً State والد را تغییر نمی‌دهند؛ رویدادها را از طریق callback prop گزارش می‌کنند. JSX چیدمان صفحه در `ShopPage` است تا `App` فقط Effect، `LoadState` و توابع رویداد را نگه دارد.

`api/` مسئول دریافت داده از شبکه و `storage/` مسئول دسترسی به `localStorage` است. قوانین سبد و انتخاب محصولات در توابع مستقل `features/` قرار دارند و همیشه آرایهٔ جدید برمی‌گردانند. `main.tsx` فقط برنامه React را به عنصر `root` متصل می‌کند.

## 6. امنیت

هر چیزی که در مرورگر است قابل دیدن و تغییر است: Bundle، متغیرهای `VITE_`، پاسخ API و `localStorage`؛ پس هیچ رمز یا کلیدی در `.env` نمی‌گذاریم. متن‌ها به‌صورت JSX رندر می‌شوند و React مقدارهای متنی را escape می‌کند تا داده‌های API به‌عنوان HTML تفسیر نشوند؛ رنگ‌ها فقط Hex معتبر و لینک‌ها فقط Fragment معتبر می‌پذیرند (`safe-href.ts`).

جمع نهایی سبد باید در سرور حساب شود، چون کاربر می‌تواند `localStorage` را دستکاری کند یا درخواست را با قیمت و تعداد دلخواه بفرستد. عددی که مرورگر می‌فرستد فقط یک درخواست است، نه مبلغ قطعی.

خروجی `dist` با `base: './'` برای مسیر `/shops/<slug>/` ساخته می‌شود. API در توسعه `/api` و در نسخهٔ تولید `../../api` است.
