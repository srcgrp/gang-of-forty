# DESIGN

## 1. نیازمندی‌ها
### کاربر در صفحه چه کارایی میتونه بکنه:
- اگر کاربر از بخش همه دسته ها روی تنقلات کلیک کنه میره به بخش خشکبار و تنقلات
- تو قسمت پنجره شکسته وقتی کاربر روی گزارش مشکل کلیک میکنه میره به بخش پایین صفحه و تماس با ما تا بتونه شماره تلفن فروشگاه رو برداره
- وقتی کاربر تو قسمت کاروسل ها روی دکمه مشاهده همه کلیک میکنه کاروسل یکی یکی جلو میره و وقتی به اخر کاروسل برسه اگر دکمه بازگشت به ابتدا رو بزنه به اول کاروسل برکمیگرده.
- تو قسمت فوتر بخش دسته بندی ها وقتی کاربر روی تنقلات میزنه میره به بخش خشکبار و تنقلات
- وقتی کاربر یه محصول رو به سبد خریدش اضاف میکنه براش یه پیام میاد که محصول به سبد خرید اضافه شد ولی چیزی ذخیره نمیشه و شمارنده سبد خرید عوض نمیشه.
- تو بخش دسته بندی ها اگر کاربر بزنه روی تنقلات میره به بخش خشکبار و تنقلات
- کاربر میتونه محصولات تخفیف دار رو تو کاروسل پیشنهاد ویژه ببینه
- در انتهای صفحه کاربر با کلیک روی دکمه بازگشت به بالا به ابتدای صفحه برمیگرده


### چه چیزی عمدا خارج ازین نسخه ست؟
- (دکمه سبد خرید فقط ظاهریه) سبد خرید واقعی
- اینکه کاربر بتونه محصولات رو با جستجو کردن پیدا کنه
- ـ(دکمه ورود ظاهریه) لاگین کردن کاربر
- کلیک روی کارت محصول چیزی رو باز نمیکنه 
- دارک مد نداره
- موجودی انبار تو کارت محصولاتم نشون داده نمیشه
- دکمه شروع خرید روی بنر کاری انجام نمیده

## 3. داده‌ها و صاحبشان
- نوار اعلان رو از ای پی آی گرفتم پس میشه سرور 
- بخش تنقلات (با رفرش از بین نمیره و توی آدرس بالای صفحه نوشته میشه ) پس میشه url
- اسلاید فعلی هر کاروسل (فقط تو حافظه همین تب هستن اگر رفرش بزنم به حالت اولیه برمیگردن) پس میشه state
- منوی ناوبری و همبرگری رو از سرور گرفتم پس اینم میشه سرور
- محتوای کارت های محصول از سرور 
- بخش هایی از فوتر مثل دسته ها و قسمت تماس با ما و درباره فروشگاه رو از ای پی آی گرفتم یعنی سرور 
- آدرس api  از .env میاد

## 4. قرارداد API

- فایل product.json رو به شکل product[] برای دو کاروسل پیشنهاد ویژه و خشکبار
- فایل stock.json رو به شکل { items: Record<number, number>} برای ناموجود بودن کارت های محصول
- فایل offers.json به شکل Offer[] برای کاروسل پیشنهاد ویژه ینی قیمت های قدیمی  و جدید و تخفیف ها
- فایل categories.json به شکل Category برای بخش همه دسته ها - منو همبرگری - دسته بندی های فوتر و دسته بندی ها
- فایل shop.json به شکل shop برای بخش نوار اعلان آدرس و شماره (تماس با ما)- شعار و متن درباره ما (فوتر)- لینک های منو ناوبری

## 5. حالت‌ها
- loading =فچ زده شده ولی هنوز تموم نشده - دسته بندی ها و پیشنهاد ویژه و تنقلات پیام در حال بارگذاری رو نشون میدن.
- success=فایل ها اومدن و توشون محصول بود - کارت های محصول و دسته بندی ها درست بارگذاری میشن
- error=اینترنت قطع باشه یا اسم فایل رو اشتباه زده باشم و فایل پیدا نشه =متاسفیم محصولات بارگذاری نشدند.
- empty= فایل سالم اومده ولی لیستش خالیه - این پیامو نشون میده :متأسفیم، محصولات بارگذاری نشدند. لطفاً دوباره تلاش کنید.

## 7. امنیت

### چه چیزی در مرورگر عمومیه؟ 
همه‌چی: کد JS، فایل‌های API (products، stock، offers، categories، shop که شماره‌تلفن هم توشه)
و مقدارهای VITE_ توی .env که موقع build تو کد می‌شینن. کاربر با F12 همه‌شون رو می‌بینه
و می‌تونه عوضشون کنه. پس هیچ رمز و کلید محرمانه‌ای اونجا نمی‌ذاریم.
داده‌ی API رو هم همیشه با textContent می‌ذاریم نه innerHTML



### چرا جمع نهایی سبد خرید رو سرور باید حساب کنه؟
چون هر چی تو مرورگر حساب بشه دست کاربره. مثلاً قیمت بعد از تخفیف الان تو مرورگر
حساب می‌شه و کاربر با F12 می‌تونه عددش رو عوض کنه یا درخواستی که می‌ره رو دستکاری کنه.
پس عددی که تو صفحه می‌بینه فقط نمایشه. وقتی سبد واقعی داشتیم، مرورگر فقط می‌فرسته
.کدوم محصول، چند تا و سرور با قیمت، تخفیف و موجودی خودش جمع رو حساب می‌کنه.
