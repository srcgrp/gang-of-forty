# طراحی سوپرمارکت بوی کد

## ۱. نیازمندی‌ ها

- کاربر می‌ تواند کالاها را با قیمت، تخفیف و وضعیت موجودی ببیند.
- کاربر می‌ تواند یک دسته را انتخاب کند و کالاهای همان دسته را ببیند.
- کاربر می‌ تواند کالای موجود را به سبد اضافه کند یا از سبد حذف کند.
- سبد خرید بعد از Refresh باقی می‌ ماند و تعداد و جمع آن نمایش داده می‌ شود.

## ۲. بخش‌ های صفحه

- نوار اطلاع‌ رسانی با افکت تایپ، هدر و منوهای دسکتاپ و موبایل.
- بنر اصلی و دسته‌ بندی کالاها.
- بخش پیشنهادهای ویژه و کارت دریافت کد تخفیف با افکت آتش ‌بازی.
- کاروسل ‌های محصولات، دکمه ی سبد خرید و پنل سبد.
- راهنمای خرید، پرسش‌ های پرتکرار و فوتر.


## ۳. داده‌ ها و صاحبشان

- اطلاعات سرور: محصولات، قیمت ‌ها، موجودی، تخفیف‌ ها، دسته‌ ها و محتوای فروشگاه از API می‌ آیند.
- وضعیت برنامه: داده‌ های دریافت ‌شده، حالت بارگذاری، دسته ی انتخاب‌ شده، سبد و بازبودن پنل سبد در App نگه داشته می‌ شوند.
- حافظه ی مرورگر: یک نسخه از سبد در localStorage ذخیره می ‌شود تا بعد از Refresh باقی بماند.
- آدرس صفحه: از Fragmentهایی مثل  #products برای رفتن به بخش ‌های صفحه استفاده می ‌شود.
- تنظیمات محیطی: آدرس API در فایل ‌های .env مشخص می ‌شود.
- فایل‌ های پروژه: نام اختصاصی فروشگاه، لوگو و تصاویر داخل پروژه هستند.


## ۴. قرارداد API

در شروع برنامه، یک useEffect تابع loadShopData را اجرا می ‌کند.
این تابع شش فایل زیر را با Promise.all می ‌گیرد:


- کالاها از فایل products.json می ‌آیند و نوعشان Product[]  است.
- دسته ‌ها از فایل categories.json می ‌آیند و نوعشان Category[] است.
- تخفیف ‌ها از فایل offers.json می ‌آیند و نوعشان Offer[] است.
- موجودی کالاها از فایل stock.json می ‌آید و نوع آن Stock است.
- اطلاعات فروشگاه از فایل shop.json می‌ آید و نوع آن Shop است.
- محتوای صفحه ی اصلی از فایل home.json می ‌آید و نوع آن Home است.


خروجی getJSON از نوع unknown است و Guardها داده ‌ها را قبل از استفاده بررسی می ‌کنند.
محصولات نامعتبر حذف می‌ شوند و تعدادشان در Console نوشته می ‌شود.

اگر Effect پا‌کسازی شود، پرچم ignore باعث می ‌شود جواب درخواست قبلی، State  را عوض نکند.

## ۵. حالت‌ های صفحه

- حالت بارگذاری : (loading) پیام "در حال بارگذاری فروشگاه..." نمایش داده می ‌شود.
- حالت موفق : (success)  فروشگاه با اطلاعات بررسی‌ شده نمایش داده می ‌شود.
- حالت خالی : (empty) اگر هیچ کالای معتبری دریافت نشود، پیام "کالایی پیدا نشد!" نمایش داده می‌ شود.
- حالت خطا : (error) پیام "خطای دریافت" یا "بررسی اطلاعات" نمایش داده می‌ شود.

اگر دریافت اطلاعات بیشتر از سه ثانیه طول بکشد، پیام "اتصال کند" نمایش داده می ‌شود.
کامپوننت Status این حالت‌ ها را با switch بررسی می‌ کند و در default بررسی never دارد.
اگر دسته ‌ای کالا نداشته باشد، پیام خالی ‌بودن در همان کاروسل نمایش داده می ‌شود.
فایل‌ های broken.json و missing.json برای امتحان ‌کردن حالت خطا استفاده شدند.


## ۶. پوشه‌ ها و فایل ‌ها

```text
src/
  types.ts
  api/
  storage/
  data/
  cart/
  catalog/
  components/
  App.tsx
  main.tsx
```

- فایل types.ts: نوع‌ های مشترک و فیلترهای فروشگاه در این فایل هستند و چیزی import نمی ‌کند.
- پوشه api/: فایل ‌های JSON را می ‌گیرد و داده‌ ها را با Guardها بررسی می ‌کند.
- پوشه storage/: سبد را از localStorage می‌خواند، داده ی ذخیره‌شده را بررسی می‌ کند و تغییرات سبد را ذخیره می‌ کند.
- پوشه data/: توابع مربوط به URL از هفته چهارم در این پوشه هستند.React از آن‌ استفاده نمی‌ کند.
- پوشه cart/: کارهای سبد مثل افزودن، حذف، شمارش و محاسبه ی جمع را با تابع‌ های خالص انجام می ‌دهد.
- پوشه catalog/: محصولات و کاروسل ‌ها را انتخاب می‌ کند، قیمت و موجودی را بررسی می‌ کند و داده‌ های لازم - برای صفحه را آماده می ‌کند.
- پوشه components/: بخش ‌های صفحه با JSX در این پوشه نوشته شدند. کامپوننت‌ها props می ‌گیرند و در صورت نیاز، رویدادها را با callback به بالا خبر می‌ دهند.
- فایل App.tsx: Stateها، Effectهای دریافت داده، ذخیره ی سبد و عنوان تب، و رویدادهای اصلی برنامه را مدیریت می ‌کند.
- فایل main.tsx: کامپوننت App را با createRoot و StrictMode داخل عنصر root نمایش می‌ دهد.

افکت تایپ در Announcement و افکت آتش‌بازی در DiscountCard اجرا می ‌شوند.
هرکدام cleanup خودشان را دارند تا منابع قبلی را پاک کنند.


## ۷. امنیت

- طلاعات localStorage قابل تغییرند و متغیرهای VITE_ داخل کد نهایی مرورگر دیده می‌ شوند.
- نمایش متن ‌های API در کامپوننت‌ ها با JSX انجام می‌ شود. افکت تایپ هم در حالت متن ساده اجرا می ‌شود.
- سرور باید هنگام ثبت سفارش واقعی، قیمت، تخفیف، موجودی و جمع نهایی را دوباره بررسی کند؛ چون کاربر می ‌تواند اطلاعات داخل مرورگر را تغییر دهد.

## ۹. وضعیت‌ ها (State) در کجا نگه داشته می‌ شوند؟

| وضعیت (State) | کامپوننت&nbsp;صاحب | چه کسی عوضش می‌ کند؟ | کجا ذخیره می‌ شود؟ |
| ---: | :---: | ---: | ---: |
| اطلاعات و حالت بارگذاری (state از نوع LoadState) | App | پاسخ درخواست‌ های API در Effect دریافت داده | حافظه React |
| دسته ی انتخاب‌ شده (categoryId) | App | انتخاب دسته از منوها، کارت‌ ها و لینک‌ های صفحه |حافظه React |
| سبد خرید (cart) | App | کلیک افزودن و حذف، با تابع‌ های خالص پوشه ی cart |حافظه React و localStorage |
| باز بودن پنل سبد (cartOpen) | App | دکمه ی سبد خرید و دکمه ی بستن پنل |حافظه React  |


برای موارد زیر State جدا نگرفتم، چون از داده‌ های موجود حساب می ‌شوند:

- محصولات و کاروسل‌ های قابل نمایش از داده‌ های API و categoryId به دست می‌ آیند.
- تعداد سبد را cartCount از cart حساب می ‌کند.
- ردیف ‌های سبد را cartRows از سبد، محصولات و تخفیف ‌ها می‌ سازد.
- جمع سبد را cartTotal از ردیف ‌های سبد حساب می‌ کند.
- قیمت نهایی و وضعیت موجودی کارت ‌ها از اطلاعات محصول، تخفیف و موجودی API به دست می ‌آیند.

با هر render، این مقادیر دوباره از داده ‌های فعلی محاسبه می ‌شوند.
