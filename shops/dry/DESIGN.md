# طراحی فروشگاه MARTO (shops/dry)

## ۱. نیازمندی‌ها

کاربر می‌تواند:
- پیشنهادهای ویژه و لبنیات را در کاروسل ببیند
- محصولات را جستجو کند (جستجوی فارسی که به اشتباه تایپی هم حساس نیست)
- محصول را به سبد اضافه کند و تعداد سبد را در هدر ببیند
- بفهمد کدام محصول ناموجود است
- دسته و متن جستجو را در آدرس نگه دارد (با Refresh یا فرستادن لینک همان نتیجه دیده شود)

بعد از تمام شدن معماری اضافه می‌شود:
- دکمه‌ی علاقه‌مندی (♡) که انتخاب کاربر را در localStorage نگه می‌دارد
- صفحه‌ی جدا برای هر محصول (آدرس #/product/<id>)
- صفحه‌ی سبد خرید با تغییر تعداد و حذف

عمداً در این نسخه نیست: ورود و ثبت‌نام، پرداخت و ذخیره‌ی سبد روی سرور،
چون API فقط فایل JSON خواندنی است و خروجی dist باید روی هر سرور استاتیکی کار کند.

## ۲. بخش‌های صفحه

هدر (لوگو، جستجو، سبد) · منوی دسته‌ها · نتایج جستجو · هیرو ·
دسته‌بندی‌ها · پیشنهادهای ویژه · لبنیات · بنرها · مجله · فوتر.

بخش‌هایی که با داده‌ی API پر می‌شوند: پیشنهادهای ویژه، لبنیات، نتایج جستجو.
بقیه ثابت و داخل index.html هستند.

## ۳. داده‌ها و صاحبشان

| داده | صاحب | کجا زندگی می‌کند |
|---|---|---|
| لیست محصولات، موجودی، پیشنهادها | سرور | api/*.json (فقط خواندنی) |
| وضعیت بارگذاری (LoadState) | برنامه | حافظه؛ features/products/api/load.ts می‌سازد و features/products/ui/state.ts نشان می‌دهد |
| سبد (آرایه‌ی CartLine: id و qty) | کاربر | حافظه‌ی main.ts و localStorage با کلید dry-cart (فقط داخل features/cart/storage/cartStorage.ts
| دسته‌ی انتخاب‌شده و متن جستجو | کاربر | URL (category و q)، فقط داخل features/products/storage/urlState.ts |
| محصولات علاقه‌مندی (بعداً) | کاربر | localStorage، کلید dry-favorites |
| آدرس API | پروژه | env، متغیر VITE_API_URL، خوانده‌شده در features/products/api/http.ts |

## ۴. قرارداد API

| فایل | نوع در types.ts | Type Guard |
|---|---|---|
| products.json | Product[] | isProduct |
| stock.json | Stock | isStock |
| offers.json | Offer[] | isOffer |
| categories.json | Category[] | isCategory |

هر پاسخ اول `unknown` است و فقط بعد از رد شدن از Guard به نوع واقعی تبدیل می‌شود.
محصول یا تخفیفی که از Guard رد نشود حذف می‌شود و تعدادش در Console نوشته می‌شود.
سبد ذخیره‌شده در localStorage هم از بیرون می‌آید و با isCartLine چک می‌شود.
فعلاً صفحه از categories.json و shop.json استفاده نمی‌کند؛ Guard و نوع‌شان آماده است.

## ۵. حالت‌ها

وضعیت هر بخش‌ِ کاروسل یک Union به نام LoadState است (loading, success, empty, error)
و ui/state.ts آن را با switch و بررسی never نشان می‌دهد.

| بخش | loading | success | empty | error |
|---|---|---|---|---|
| پیشنهادهای ویژه | «در حال بارگذاری...» | کارت‌ها در کاروسل | «محصولی برای نمایش وجود ندارد» | پیام فارسی با role=alert |
| لبنیات | مثل بالا | مثل بالا | مثل بالا | مثل بالا |
| نتایج جستجو | — | تعداد نتایج و کارت‌ها | «نتیجه‌ای پیدا نشد» یا «محصولی در این دسته نیست» | — |

## ۶. پوشه‌ها

```
src/
  main.ts            State، رویدادها، شروع برنامه؛ تنها جایی که به هر دو Feature می‌رسد
  shared/
    types.ts         مدل داده، هیچ چیز import نمی‌کند
    checks.ts        بررسی‌های ساده‌ی نوع (رشته، عدد، شیء) که هر دو Feature لازم دارند
  features/
    products/
      api/           fetch، Guard ها و بارگذاری (تنها جایی که fetch دارد)
      storage/       خواندن و نوشتن URL (تنها جایی که به آن دست می‌زند)
      catalog/       قیمت، موجودی، دسته، جستجو، ساخت کارت (توابع خالص)
      ui/            ساختن و تغییر DOM: صفحه، کارت، وضعیت
    cart/
      rules/         قانون‌های سبد (توابع خالص)
      storage/       localStorage سبد (تنها جایی که به آن دست می‌زند)
      ui/            شمارنده‌ی سبد و پیام موفقیت
```

قانون‌ها:
- داخل هر Feature جهت import ها همان است: ui و catalog و api و storage ← shared.
- دو Feature هیچ‌وقت مستقیم از هم import نمی‌کنند؛ فقط main.ts به هر دو می‌رسد.
- ui فقط shared را می‌شناسد؛ قیمت و متن را main از catalog می‌گیرد و به شکل Card به ui می‌دهد.
## ۷. امنیت

هر چیزی که در مرورگر است عمومی است: کد، متغیرهای VITE_، localStorage و URL.
کاربر می‌تواند در DevTools تعداد سبد، قیمت‌ها و کد را عوض کند یا آدرس را دست‌کاری کند.
پس هیچ کلید یا رمزی در env نمی‌گذاریم، و جمع نهایی سبد باید در سرور حساب شود،
چون قیمتی که مرورگر نشان می‌دهد فقط برای نمایش است و قابل اعتماد نیست.
مقدار category و q از URL هم از بیرون می‌آید: دسته‌ی ناشناخته نادیده گرفته می‌شود
و متن جستجو فقط با textContent نشان داده می‌شود، نه به‌صورت HTML.
