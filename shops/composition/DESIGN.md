# بت‌شاپ — طرح پروژه

## ۱. سایت چه کارهایی انجام می‌دهد؟

صفحه را با React ساختم. کاربر می‌تواند محصولات و تخفیف‌ها را ببیند، دسته انتخاب کند و محصولات هر دسته را افقی ورق بزند. می‌تواند کالا به سبد اضافه کند، تعداد و جمع قیمت را ببیند و یک قلم را حذف کند. محصول ناموجود اضافه نمی‌شود و افزایش تعداد از موجودی بیشتر نمی‌شود.

اقلام سبد و تم انتخابی بعد از رفرش باقی می‌مانند. عنوان تب هم تعداد کل کالاهای سبد را نشان می‌دهد. تم برای کاربر جدید روشن است.

جست‌وجو در نسخهٔ React هنوز فعال نیست و در بخش امتیازی انجام می‌شود. فیلتر دسته فعلاً در State است و بعد از رفرش از نو شروع می‌شود. ورود کاربر، پرداخت و ثبت سفارش واقعی نداریم.

## ۲. بخش‌های صفحه

- سربرگ: لوگو، ورودی جست‌وجوی فعلاً غیرفعال، تعداد سبد و دکمهٔ تغییر تم.
- منو و دکمه‌های انتخاب دسته.
- بنرها، پیشنهادها و کاروسل محصولات.
- کارت محصول با قیمت، تخفیف، موجودی و دکمهٔ افزودن.
- سبد بازشونده با اقلام، تعداد، حذف و جمع قیمت.
- پیام بارگذاری، نبود محصول و خطا.
- فوتر و اطلاعات فروشگاه.

## ۳. داده‌های پروژه

نوع‌های مشترک در `src/shared/types.ts` هستند: `Product`، `Category`، `Stock`، `Offer`، `Shop` و `Home` برای داده‌های API؛ `CartItem` برای هر قلم سبد؛ `LoadState` برای وضعیت دریافت داده. `CardView` و `PageView` اطلاعات آمادهٔ نمایش را مشخص می‌کنند. فایل تایپ‌ها چیزی import نمی‌کند.

## ۴. اطلاعات کجا نگهداری می‌شوند؟

محصولات، قیمت، موجودی، تخفیف و محتوای فروشگاه از سرور می‌آیند. داده‌های دریافت‌شده، دستهٔ انتخابی، سبد، باز بودن سبد و تم در Stateهای `App` هستند. تعداد و جمع قیمت سبد از اقلام حساب می‌شوند و State جدا ندارند.

اقلام کامل سبد در کلید `batshop-cart` و تم در `batshop-theme` داخل `localStorage` ذخیره می‌شوند. خواندن و نوشتن آن‌ها فقط از طریق توابع storage است. دادهٔ سبد هنگام خواندن اعتبارسنجی می‌شود؛ دادهٔ خراب به سبد خالی برمی‌گردد.

کدهای جست‌وجو و URL از هفتهٔ قبل باقی مانده‌اند، اما هنوز به صفحهٔ React وصل نیستند. فعلاً جست‌وجو یا دسته از URL بازیابی نمی‌شود.

## ۵. چه اطلاعاتی دریافت می‌کنیم؟

هنگام شروع برنامه، `products.json`، `categories.json`، `stock.json`، `offers.json`، `shop.json` و `home.json` هم‌زمان دریافت می‌شوند. خروجی JSON از نوع `unknown` است و قبل از استفاده با Type Guard بررسی می‌شود. محصولات نامعتبر کنار گذاشته می‌شوند.

آدرس پایه فقط از `VITE_API_URL` می‌آید: در `.env.development` مقدار `/api` و در `.env.production` مقدار `../../api` دارد. مسیر جایگزین در کد نداریم؛ اگر متغیر تنظیم نشده باشد، تابع دریافت اطلاعات خطا می‌دهد. وضعیت HTTP هم با `response.ok` بررسی می‌شود.

## ۶. حالت‌های صفحه

`LoadState` چهار وضعیت دارد: `loading`، `success`، `empty` و `error`. پیام‌های وضعیت در `LoadStatus` با `switch` نمایش داده می‌شوند و حالت ناشناخته با `never` بررسی می‌شود. در Effect دریافت اطلاعات، cleanup پرچم `ignore` را فعال می‌کند تا پاسخ قدیمی State را عوض نکند.

## ۷. کدها را چطور تقسیم کردم؟

- `src/main.tsx`: اتصال React به عنصر root و فعال کردن StrictMode.
- `src/App.tsx`: Stateها، Effectها و مدیریت رویدادها.
- `src/components`: نمایش صفحه با JSX و Props تایپ‌دار؛ ظاهر اصلی در `ShopView` است.
- `src/features/products`: دریافت و اعتبارسنجی دادهٔ محصولات و آماده‌سازی کارت‌ها و دسته‌ها.
- `src/features/cart`: توابع خالص افزودن، حذف، تعداد و جمع قیمت؛ اعتبارسنجی و ذخیرهٔ سبد.
- `src/shared`: تایپ‌ها، قالب‌بندی، دریافت داده‌های مشترک و storage تم و URL.

UI قدیمی و `src/main.ts` حذف شده‌اند. هیچ فایل TypeScript یا TSX بیشتر از ۷۰ خط نیست. کامپوننت‌ها مستقیم fetch یا localStorage را صدا نمی‌زنند. منطق خالص هم به DOM، شبکه و storage دسترسی ندارد. ارتباط محصولات و سبد با callbackها در App برقرار می‌شود؛ Featureها مستقیماً از هم import نمی‌کنند.

## ۸. امنیت

متغیرهای `VITE_` داخل خروجی مرورگر قابل مشاهده‌اند؛ هیچ رمز یا کلید محرمانه‌ای در آن‌ها قرار نمی‌دهم. فایل‌های `.env*.local` هم در Git ثبت نمی‌شوند.

دادهٔ API و localStorage را قابل اعتماد فرض نمی‌کنم و قبل از استفاده ساختارشان را بررسی می‌کنم. متن محصولات با JSX نمایش داده می‌شود و از `dangerouslySetInnerHTML` استفاده نمی‌کنم.

قیمت، موجودی و سبد داخل مرورگر قابل تغییرند. در فروشگاه واقعی سرور باید هنگام ثبت سفارش دوباره قیمت، موجودی و مجوز خرید را بررسی کند؛ بررسی سمت مرورگر جای این کار را نمی‌گیرد.
